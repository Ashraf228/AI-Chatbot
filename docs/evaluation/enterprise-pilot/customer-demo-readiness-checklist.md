# Customer Demo Readiness Checklist

## Before Scheduling

- access path tested
- correct URL confirmed
- user and role confirmed
- Demo Workspace reachable
- no customer data will be used
- caveat language prepared
- test instructions prepared

## Required Caveats To Say Before Demo

- This demo is not production.
- No customer data may be used.
- No confidential documents may be uploaded.
- No real passwords, tokens, or secrets may be entered.
- No real ticket, email, or webhook execution occurs.
- No public widget is being activated.
- No deploy is being performed.
- Response speed is still being optimized.
- Conversation Engine behavior is still being refined.

## Demo Flow

1. Login
2. Open workspace
3. Configure agent
4. Save or load config
5. Add knowledge snippet
6. Add PDF demo knowledge
7. Use test chat
8. Explain boundaries
9. Capture feedback

## Pass Criteria

- login works
- workspace is understandable
- agent configuration is understandable
- knowledge is used in answers where relevant
- safety boundaries remain visible and intact
- handoff is simulated only
- no forbidden actions are implied

## Stop Criteria

- customer wants to upload real data
- customer wants to test the public widget
- customer wants a deploy
- customer wants a real integration
- customer wants a final performance benchmark
- customer wants to derive DSGVO or enterprise approval from the demo

## After Demo

- document feedback
- prioritize technical gaps
- decide whether the next step is another pilot gate or a product feature gate
